# Laboratory 07 – Cloud Operations Engineer

## Mission Overview

In this laboratory, I performed basic server monitoring and Docker container observation using the KillerCoda Ubuntu Playground. I checked the server's available resources, started an Nginx web server, tested website requests, and examined the logs and performance statistics of the container.

This activity introduced me to the responsibilities of a Cloud Operations Engineer, especially monitoring system performance and checking whether an application is working as expected.

## Objectives

The objectives of this laboratory were to:

- Examine the server's memory and disk capacity.
- Monitor CPU usage and active processes in Linux.
- Run an Nginx web server using Docker.
- Test the website by sending HTTP requests with curl.
- Observe the server's response to a request for a missing webpage.
- Review container logs to find successful and failed requests.
- Measure container resource usage through Docker's monitoring tool.
- Record the activities and results in a GitHub portfolio.

## Monitoring Commands Executed

The following commands were used during the laboratory:

| Command | Description |
|---|---|
| free -h | Displays the server's memory information in a readable format. |
| df -h / | Shows the storage capacity and usage of the root file system. |
| top | Monitors running processes and current system activity. |
| docker run -d --name clientwebsite -p 8080:80 nginx | Creates and starts the Nginx container in the background. |
| docker ps | Lists running Docker containers. |
| curl http://localhost:8080 | Checks whether the Nginx website responds to a request. |
| curl http://localhost:8080/hidden-admin-page | Tests the response for a webpage that does not exist. |
| docker logs clientwebsite | Displays the logs generated by the Nginx container. |
| docker stats | Shows live CPU, memory, network, and block I/O statistics for containers. |

## Skills Learned

This activity helped me improve my skills in using Linux commands to check server resources and using Docker to run a web application. I learned how to test a website with HTTP requests and recognize the difference between a successful response and a 404 error.

I also gained experience reading application logs and monitoring container performance. These skills are important because they help cloud operations teams understand application behavior, detect errors, and identify possible resource issues.
